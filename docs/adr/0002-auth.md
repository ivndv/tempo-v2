# ADR 0002 — Auth y Postgres

- **Estado:** aceptado
- **Fecha:** 2026-10-23

## Contexto

No hay usuarios existentes. v1 usa Better Auth + Hashy (Argon2id) + KV. Se quiere reducir el código propio y aprovechar RLS.

## Decisión

- **Supabase Auth** para identidad, sesiones, verificación de email y reset.
- **Supabase Postgres** para datos de la aplicación.
- **`@supabase/ssr`** con cookies httpOnly y refresco en `proxy.ts`.
- **RLS** en tablas de usuario; `profiles.id = auth.users.id`.
- Se retiran Hashy, Better Auth, KV y la tabla `rate_limit` propia.

## Consecuencias

- No hay migración de contraseñas: el proyecto arranca sin usuarios.
- Todo el acceso a datos de usuario pasa por el cliente de Supabase, de modo que RLS sea la frontera de autorización.
- Los dashboards se resuelven con vistas o funciones RPC; el service role se reserva para webhooks y tareas administrativas.
- El webhook de Polar y las operaciones administrativas usan el service role solo en servidor.
- Supabase Auth requiere configurar SMTP (Resend) y Turnstile en el dashboard.
